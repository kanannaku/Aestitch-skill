# Taste discovery: compare situations, not labels

Aestitch records **observations**, not a universal personal style. An A/B result without context should not override a page-specific design constraint.

## Recommended interview

1. Pick 2–4 *legitimate* sources that differ in composition, density, typography or interaction; cite the source and the exact visual feature.
2. Present a short comparison, not a long questionnaire. Allow both/neither/unsure. Ask at most one follow-up: "Which specific detail draws you in?" If the user cannot articulate it, preserve the exact choice without inventing a reason.
3. Follow up with one controlled comparison: retain most variables and change only typography or only layout, if feasible. Distinguish design quality from stylistic preference.
4. Record `taste compare` **only after** a user choice. New evidence does not automatically overwrite other contexts.
5. Generate `taste report`; cite concrete reference IDs and the user's words. Label all broader conclusions as *hypotheses* until confirmed by repeated observations or user acceptance.

## Reference evidence

- A URL alone is **not** evidence the site has been viewed. CLI `reference add --url` only records metadata.
- A screenshot is **not** evidence of scroll, hover, focus or responsive behavior.
- If an agent actually visits a URL or examines a screenshot, include a short observation and mark its provenance separately in discussion. Do not blindly copy code or art.
- Prefer a reference matrix: `source → dimension (type/layout/motion) → observation → suitability → open questions`.

## Negative choices

Don't convert one rejection into a global ban. "Not this purple gradient on this home page" != "Never use purple anywhere". Contradictory tastes can coexist in separate project contexts.
